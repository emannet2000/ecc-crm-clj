# Workspace workflows

Leads track contact details, assignment, pipeline stage, follow-ups and notes. Conversion creates a client and application together, transfers related work/history, and returns the existing client when retried. Archive preserves records; administrators restore from Archive.

Applications hold service/institution/course details, deadlines, checklist requests and milestones. Apply a template from an application row; repeated application does not duplicate its items. Client detail opens notes, tasks, applications, uploads, the student profile and photo controls. Search the record selector when creating work for a record outside the first page.

Tasks support assignment, scheduling/deadlines, recurrence and cancellation. Completion creates the next occurrence once. Configure Reminder rules and notification preferences for deadline/escalation email. Appointments support overlap checks, client visibility, Zoom and Google Calendar actions, and calendar export.

Documents and photos are quarantined. Upload a checklist version before marking it received, and wait for a clean scan before approval/download. Use Compare to review current server values after a stale-save conflict.

Draft proposals/contracts can be issued and answered through restricted client portal links. Portal links are one-use. Responses enumerate public fields, omit internal notes/profile identifiers, and enforce client ownership. Files remain private until staff explicitly grant a latest approved, clean and unexpired checklist version; replacing or expiring that version removes access. Signed provider PDFs remain quarantined until scanned.

Issue an invoice before recording payment or requesting checkout. Posting uses integer cents, one submission identity per operation, and immutable reversal entries. Expenses require a separate approver, then payment; reversal retains posted history. Closed periods reject financial changes. Bank reconciliation imports date/amount/currency/reference CSV rows and matches posted payments or paid expenses of the same currency/amount. Unmatching/ignoring requires a reason.

Finance access is granted explicitly through Team access controls. Viewer role ceilings remain in force even if an administrator selects write privileges. Reports/export, attachment downloads and provider operations are checked on the server; disabled UI buttons are additional guidance.

Team supports invitations, scope/privilege editing, suspension and session revocation. Account security supports authenticator enrollment, one-use recovery codes and password change. Administrators can reset another account's authenticator after password verification. Saved views retain each user's own query/entity/mine/overdue settings.
